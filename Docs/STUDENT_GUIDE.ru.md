# Career Explore POC — руководство для студента

*Как устроен проект, как он создавался и как его развивать дальше. Основной фокус — Kotlin и Android.*
*English version: [STUDENT_GUIDE.md](STUDENT_GUIDE.md)*

## 1. Что мы делаем

**Career Explore** — приложение для планирования карьеры для людей 18–35 лет. Пользователь проходит **четыре шага**:

1. **Interests (интересы)** — составить список из 20+ интересных занятий и выбрать два главных.
2. **My Best (мои лучшие моменты)** — описать моменты, когда вы были «на высоте», и почему.
3. **Values (ценности)** — выбрать ровно 3 ценности, без которых работа не приносит удовольствия.
4. **Get Excited (что вдохновляет)** — что вас вдохновляет, ваши «хочу» в работе, до трёх целей, а для каждой цели — препятствия и ресурсы.

В конце приложение строит **личный план на 3 месяца**. Его можно экспортировать в PDF, отправить другим или связаться с коучем.

Это **POC (proof of concept)** — рабочая демо-версия, которая запускается на вашем компьютере и в эмуляторе Android. Это не готовый продукт для магазина приложений.

Описание продукта взято из документов Career Explore (Development Guidelines, Concept Note, Project Overview). Дизайн экранов сделан в **Google Stitch** (`Docs/ui/stitch/`).

## 2. Общая картина

Проект состоит из трёх частей:

```
 ┌──────────────────────┐        интернет (HTTP + JSON)        ┌──────────────────┐      ┌────────────┐
 │  Android-приложение  │  ───────────────────────────────▶   │  Сервер (API)    │ ───▶ │ PostgreSQL │
 │  Kotlin + Compose    │  ◀───────────────────────────────   │  Node.js         │ ◀─── │ база данных│
 │  (это ваша часть)    │                                     │  (уже готов)     │      │ (Docker)   │
 └──────────────────────┘                                     └──────────────────┘      └────────────┘
```

- **Приложение** показывает экраны, проверяет введённые данные и сохраняет ответы на телефоне.
- **Сервер** хранит ответы каждого пользователя, строит план и считает ключевые слова для раздела Insights.
- **База данных** хранит всё на диске.

Почему разные языки? Стажировка — для **Kotlin-разработчика**, поэтому приложение на Kotlin. В документации компании указан сервер на Node.js, и сервер сделан по ней. Приложение и сервер «общаются» только через **API** (адреса вида `/api/v1/journey/current`), которое описано в файле `openapi.yaml`. Поэтому над приложением можно работать, не зная Node.js.

## 3. Перед началом работы

Установите:
- **Android Studio** (в неё входят Android SDK и эмулятор)
- **JDK 21** (нужен только для сборки из командной строки)
- **Node.js LTS** и **Docker Desktop** (для запуска сервера и базы данных)

Запуск проекта (также описан в `README.md`):

```powershell
# 1. База данных + сервер (в одном терминале)
docker compose up -d db
cd server
npm install
npm run db:generate    # готовит код клиента базы данных
npm run db:migrate     # только в первый раз
npm run db:seed        # только в первый раз
npm run dev            # оставить запущенным

# 2. Приложение: откройте папку "client" в Android Studio → выберите "androidApp" → нажмите Run
```

> **Важно:** внутри эмулятора адрес `10.0.2.2` означает «мой компьютер». Поэтому приложение обращается к `http://10.0.2.2:3000/api/v1`.

        ├─ domain/                ← ЧТО приложение знает
        │   ├─ Models.kt          ←   data-классы (Journey, Plan, Objective…)
        │   ├─ Rules (Validation.kt) ← правила: «минимум 5 интересов», «ровно 3 ценности»…
        │   └─ Content.kt         ←   тексты, 20 ценностей, списки подсказок
        ├─ data/                  ← ОТКУДА берутся данные
        │   ├─ CareerApi.kt / KtorCareerApi.kt  ← общение с сервером
        │   ├─ JourneyRepository.kt             ← сохраняет на телефоне и отправляет на сервер (офлайн)
        │   └─ KeyValueStore.kt                 ← маленькое локальное хранилище, «сессия» пользователя

        ├─ nav/Navigator.kt       ← какой экран открыт, кнопка «Назад»
        ├─ ui/                    ← КАК это выглядит
        │   ├─ AppState.kt        ←   общее состояние (пользователь, путь, онлайн/офлайн)
        │   ├─ AutoSave.kt        ←   автосохранение каждые 30 секунд и при уходе с экрана
        │   ├─ Shell.kt           ←   верхняя панель, нижнее меню, общий макет шагов
        │   ├─ components/        ←   кнопки, поля ввода, «чипы», карточки, кольцо прогресса
        │   └─ screens/           ←   сами экраны
        ├─ AppContainer.kt        ← «собирает» приложение (API + хранилище + репозиторий)

Запомните три слоя: **domain → data → ui**. Интерфейс (ui) использует данные (data) и логику (domain). Логика ничего не знает об интерфейсе. Поэтому код легче тестировать и менять.

## 6. Главные идеи, которые вы встретите

### 6.1 Экран — это функция
В Compose экран — это функция Kotlin с аннотацией `@Composable`. Она описывает, что показать для текущих данных:

```kotlin
@Composable
fun Greeting(name: String) {
    Text("Hi, $name")
}
```

### 6.2 Состояние: данные меняются — экран перерисовывается сам
```kotlin
var items by remember { mutableStateOf(listOf<String>()) }
// ...
items = items + "Photography"   // экран обновится автоматически
```
`remember` хранит значение, пока экран виден. `mutableStateOf` говорит Compose следить за этим значением. Изменение значения запускает «рекомпозицию», то есть экран перерисовывается.

### 6.3 Data-классы и JSON
```kotlin
@Serializable
data class InterestsStep(val items: List<String> = emptyList(), val topTwo: List<String> = emptyList())
```
`@Serializable` позволяет отправить объект на сервер в виде JSON: `{"items":[...],"topTwo":[...]}`. Названия полей должны совпадать с сервером, см. `openapi.yaml`.

### 6.4 `suspend` и корутины
Запросы в сеть занимают время. Функции, которые ждут, помечены `suspend` и запускаются внутри корутины (`launch { ... }`), чтобы интерфейс продолжал работать:
```kotlin
app.launch { val plan = app.container.api.generatePlan(journeyId) }
```

### 6.5 Правила живут отдельно от экранов
Все правила шагов собраны в одном объекте `Rules` (`domain/Validation.kt`). Тексты сообщений взяты из Guidelines (раздел 8.3):
```kotlin
fun canProceedInterests(items: List<String>): Check =
    if (items.size >= 5) Check.Ok
    else Check.fail("Add a few more interests to continue - aim for at least 5 to start seeing patterns.")
```
Экраны только спрашивают «всё в порядке?» и показывают сообщение. Так как `Rules` не зависит от интерфейса, его легко покрыть модульными тестами.

> Тексты в самом приложении — на английском: продукт сначала выходит на английском языке (Guidelines 9.2).

## 7. Как движутся данные (пример: пользователь добавляет интерес)

```
Пользователь нажимает «Add»
   → InterestsScreen: items = items + "Photography"     (экран обновился)
   → через 30 секунд или по «Save & Continue» / «Back»:
       AppState.saveStep(...)
         → JourneyRepository.saveStep(...)
             1) сохранить копию на телефоне (SharedPreferences)  ← работает всегда
             2) отправить PUT /api/v1/journey/{id}/interests       ← нужен интернет
             3) нет интернета? → положить в очередь → отправить позже
```

**Офлайн-режим:** если сервер недоступен, пользователь может продолжать работу. Ответы ждут в очереди. Когда связь вернётся (при следующем запуске, по кнопке «Try again» или Profile → «Sync now»), очередь отправится.

**Правило конфликтов (Guidelines 6.6):** если копия на сервере **новее** ожидающего локального изменения больше чем на 5 минут, побеждает сервер. Это в файле `data/SyncPolicy.kt`.

**План** строится на сервере (`POST /plan/generate`), приложение его только показывает. Каждая новая генерация — новая версия: v1, v2…

## 8. Как создавалось приложение — шаг за шагом

Ниже порядок, в котором мы работали. Если будете что-то переделывать или добавлять, держитесь того же порядка: **сначала логика, экраны — в конце**.

### Шаг 1 — Каркас проекта
- Создали Gradle-проект с двумя модулями (`composeApp`, `androidApp`) и простым экраном «Hello».
- Проверили, что он собирается и запускается в эмуляторе.
- *Чему учимся:* Gradle, модули, `MainActivity`, `setContent { }`.

### Шаг 2 — Модели данных
- Описали `data class` для всего, что сервер принимает и отдаёт (`domain/Models.kt`).
- Сверили их с настоящими ответами сервера (`commonTest/Fixtures.kt`).
- *Чему учимся:* data-классы, nullable-типы (`?`), `@Serializable`, enum.

### Шаг 3 — Правила и тесты
- Перенесли все правила из Guidelines в `Rules` (минимум 5 интересов, ровно 3 ценности, минимум 3 пункта «что вдохновляет»…).
- Написали для них модульные тесты (`RulesTest.kt`).
- *Чему учимся:* «чистые» функции, модульные тесты, почему логике не место внутри экранов.

### Шаг 4 — Общение с сервером
- `CareerApi` — это **интерфейс**, список того, что можно спросить у сервера.
- `KtorCareerApi` — настоящая реализация на Ktor.
- В тестах используется «поддельный» сервер (Ktor `MockEngine`), поэтому тестам не нужен интернет.
- *Чему учимся:* интерфейсы, HTTP GET/PUT/POST, JSON, `suspend`-функции, обработка ошибок (`ApiException`).

### Шаг 5 — Сохранение офлайн
- `JourneyRepository` сначала сохраняет локально, потом отправляет. Если отправка не удалась, изменение остаётся в очереди.
- Проверено тестами с «поддельным» API, которое умеет «уходить в офлайн» (`JourneyRepositoryTest.kt`).
- *Чему учимся:* паттерн «репозиторий», локальное хранение, умение думать о плохой сети.

### Шаг 6 — Дизайн-система (из Stitch)
- Взяли цвета, шрифты и формы из файла Stitch `DESIGN.md` и перенесли их в `theme/`.
- Сделали небольшие переиспользуемые **компоненты**: `PrimaryButton`, `CeTextField`, `RemovableChip`, `CeCard`, `ProgressRing`, `SegmentedControl`…
- *Чему учимся:* темы, переиспользуемые composable-функции, `Modifier`.

### Шаг 7 — Оболочка приложения и навигация
- `Navigator` хранит список открытых экранов («back stack»). `push()` открывает экран, `back()` закрывает.
- `App.kt` показывает верхнюю панель, нижнее меню и текущий экран с анимацией перехода.
- `AppState` хранит пользователя, путь (journey) и статус онлайн/офлайн для всех экранов.
- *Чему учимся:* структура приложения, общее состояние, системная кнопка «Назад».

### Шаг 8 — Экраны, по одному
Порядок: Onboarding → Profile → Home → Шаг 1 → Шаг 2 → Шаг 3 → 4a → 4b → 4c → My Plan → Insights → Coach.
Все экраны шагов построены по одному шаблону (см. следующий раздел).

### Шаг 9 — Проверка в эмуляторе и доводка
- Прошли весь путь пользователя в эмуляторе, включая офлайн-режим, и исправили найденное: сообщения перекрывали кнопки, счётчик не обновлялся, мелочи со шрифтом.
- *Чему учимся:* ручная проверка так же важна, как модульные тесты.

## 9. Как устроен экран шага (упрощённо)

Каждый экран шага выглядит примерно так (настоящий код — в `ui/screens/StepScreens.kt`):

```kotlin
@Composable
fun InterestsScreen(app: AppState, nav: Navigator) {
    // 1. Локальное состояние, начинаем с сохранённых данных
    var items by remember { mutableStateOf(app.steps.interests?.items ?: emptyList()) }
    var input by remember { mutableStateOf("") }

    // 2. Автосохранение: каждые 30 секунд и при закрытии экрана
    val saver = rememberAutoSaver(app, InterestsStep(items)) {
        app.saveStep(StepKey.INTERESTS, it, InterestsStep.serializer())
    }

    // 3. Общий макет: заголовок, прогресс, Back / Save & Continue
    StepScreen(
        app = app, stepLabel = "Step 1 of 4 • Interests", minutes = 30, progress = 0.25f,
        title = "Interests", instruction = Content.Copy.STEP1_INSTRUCTION,
        onBack = { app.launchNow { saver.saveNow() }; nav.back() },
        onPrimary = {
            val check = Rules.canProceedInterests(items)           // 4. спрашиваем правила
            if (!check.ok) app.message(check.message!!)             //    показываем сообщение
            else { app.launchNow { saver.saveNow() }; nav.push(Screen.MY_BEST) }
        },
    ) {
        // 5. Собственное содержимое экрана
        CeTextField(value = input, onValueChange = { input = it }, label = "Add an interest")
        PrimaryButton("Add", onClick = { items = items + input.trim(); input = "" })
        items.forEach { item -> RemovableChip(item, onRemove = { items = items - item }) }
    }
}
```

Чтобы добавить новый экран шага: скопируйте шаблон, добавьте правила в `Rules`, добавьте экран в `Screen` (`Navigator.kt`) и в `ScreenContent` (`App.kt`).

## 10. Правила четырёх шагов

| Шаг | Чтобы продолжить, нужно | Другие правила |
|---|---|---|
| 1 Interests | минимум **5** | цель — 20+; не больше 60 символов; без повторов; выбор «топ-2» появляется при 20 |
| 2 My Best | **1** момент хотя бы с 1 причиной | до 6 моментов; 300 символов; мягкая подсказка, если меньше 3 |
| 3 Values | ровно **3** из 20 | 4-ю выбрать нельзя; при 3 появляется вопрос для размышления |
| 4a Get Excited | минимум **3** | до 10 строк; при 5 подсказка «что у них общего?» |
| 4b Objectives | минимум **1** цель с «I will» и «so that» | до 5 «хочу», до 3 целей |
| 4c Challenges | – | до 5 препятствий и 5 ресурсов на каждую цель |
| План | все 4 шага пройдены | каждая генерация = новая версия (v1, v2…) |

Открытие разделов: **My Plan** — после Шага 1, **Insights** — после Шага 2 (Guidelines 2.1).

## 12. Частые проблемы

| Проблема | Решение |
|---|---|
| Gradle падает со странной ошибкой Java | Используйте JDK 21 (`JAVA_HOME`); Android Studio уже использует свой JDK |
| Приложение пишет «No connection» | Запущен ли `npm run dev`? Запущен ли Docker? |
| Настоящий телефон не видит сервер | Укажите IP компьютера: `-PapiBaseUrl=http://<ip-компьютера>:3000/api/v1` и `HOST=0.0.0.0` в `.env` |
| Скриншоты эмулятора чёрные | Запустите эмулятор с `-gpu swiftshader_indirect` |
| Поменялось поле в JSON сервера | Обновите вместе `Models.kt`, `Fixtures.kt` и `openapi.yaml` |
